## What Was Built

### components/TodayLog.tsx

New client component that is the primary log view:

- Fetches `/api/meals/today` on mount and whenever `refreshKey` increments (passed from LogTab)
- Flattens `meals[].foodItems[]` to a `FoodItemWithMeal[]` array (extends `FoodItem` with `mealId`)
- **Sort pills:** 5 options (Chronological | Protein | Fat | Carbs | Fiber) as sticky pill row below header (`top-14 z-10`); active pill uses `variant="default"`, inactive uses `variant="outline"`; each has `aria-pressed`
- **sortItems** pure function: chronological returns items unchanged; nutrient sorts use descending order with `-Infinity` for nulls (nulls appear at bottom)
- **Loading state:** 3 `SkeletonCard` instances in `aria-busy="true"` container
- **Empty state:** `<section aria-label="Empty log">` with Utensils icon, "Nothing logged today" h2, and "Use the chat below to log a meal" subtext
- **Optimistic delete:** snapshot current state → filter out mealId → show Sonner toast with "Undo" (5s) → fire DELETE → restore snapshot on failure or undo click
- **SkeletonCard:** file-local component rendering `Card > CardHeader` with skeleton rows matching FoodCard header dimensions

### components/LogTab.tsx

Thin coordinator component:
- Owns `refreshKey` state (number, init 0)
- `triggerRefetch` increments refreshKey via `useCallback`
- Renders `TodayLog refreshKey={refreshKey}` and `ChatInterface onMealLogged={triggerRefetch}`
- After a meal is logged via chat, `onMealLogged` fires, refreshKey increments, TodayLog re-fetches

### app/page.tsx

Two targeted changes:
1. Import swapped from `ChatInterface` to `LogTab`
2. Authenticated branch now renders `<LogTab />` instead of `<ChatInterface />`
LandingPage branch and auth() call unchanged.

### app/layout.tsx

Two targeted changes:

2. `<Toaster />` added inside ThemeProvider after `<BottomNav />` — ThemeProvider context required for Toaster's `useTheme()` call
