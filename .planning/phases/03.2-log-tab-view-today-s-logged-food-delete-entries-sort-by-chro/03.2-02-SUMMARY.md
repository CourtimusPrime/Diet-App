## What Was Built

### components/FoodCard.tsx
New file containing the FoodCard component extracted verbatim from ChatInterface.tsx, with two additions:
- `FoodCardProps` interface with optional `mealId?: string` and `onDelete?: (mealId: string) => void`
- Trash icon button rendered in the card header only when both `mealId` and `onDelete` are present
- Exports: `FoodCard` (component), `FoodItem` (interface), `Meal` (interface), `Message` (type)

### components/ChatInterface.tsx
Two targeted changes only:
1. Removed all inline definitions (FoodCard, FoodItem, Meal, Message, HEADER_KEYS, unitFromKey, labelFromKey); replaced with imports from `@/components/FoodCard`
2. Added `ChatInterfaceProps` with `onMealLogged?: () => void`; added `onMealLogged?.()` call immediately after the `'meal'` SSE event is processed in `handleSubmit`

All other logic unchanged: message rendering, streaming, scroll behavior, input bar.

### app/api/meals/today/route.ts
GET handler scoped to authenticated user for UTC today:
- 401 if no session
- Returns `{ meals: [...] }` with nested `foodItems[]` ordered most-recent-first
- Date boundaries use UTC T00:00:00.000Z / T23:59:59.999Z pattern from existing diet route

### app/api/meals/[mealId]/route.ts
DELETE handler with full auth + ownership chain:
- 401 if no session
- 404 if meal not found
- 403 if `meal.userId === null` (orphan meal guard) OR `meal.userId !== userId` (IDOR guard)
- Returns `{ ok: true }` on success; cascade delete via Prisma schema (FoodItem onDelete: Cascade)
