# Phase 03.2: Log Tab - Context

**Gathered:** 2026-06-03
**Status:** Ready for planning

<domain>
## Phase Boundary

Replace the ephemeral chat stream on the Log tab (`/`) with a persistent, DB-backed list of today's logged food items. Users can see everything logged today at a glance, sort by key nutrients, and delete entire meals. The chat input remains at the bottom for new logging.

Scope: `/` route only. No date picker, no per-food-item delete, no chat history persistence.

</domain>

<decisions>
## Implementation Decisions

### Page Architecture
- Log tab stays at `/` — no new route needed (BottomNav already wired)
- Replace the ephemeral in-memory chat stream with a DB-fetched list of today's food items
- Chat input stays fixed at the bottom (same position as today)
- After a meal is logged via chat, the food list auto-refreshes — no full page reload
- Chat messages (user text / assistant "confirmation" text) are hidden — show only food item cards sourced from the DB

### Data & Interactions
- Delete granularity: meals only — one trash icon per meal, cascade deletes all food items in that meal
- Sort scope: flatten all food items across all meals for the day — cross-meal sorting
- Delete API: new `DELETE /api/meals/[mealId]` endpoint; auth-gated, only the meal owner can delete
- Date scope: always today's date — no date picker

### UI Design
- Sort control: horizontal scrollable pill buttons above the list — labels: Chronological | Protein | Fat | Carbs | Fiber
- Active sort pill has filled/primary style; inactive pills are outline/muted
- Delete UX: trash icon button on each meal card header. Tap = immediate delete + toast with "Undo" action (5s window). No modal.
- Empty state: centered Utensils icon + "Nothing logged today" heading + "Use the chat below to log a meal" subtext
- Loading state: skeleton cards matching FoodCard dimensions (same card shape, grey shimmer)

### Claude's Discretion
- Exact Prisma query shape for the log fetch (reuse `/api/diet` pattern or new endpoint)
- Toast library choice (use shadcn Sonner or existing toast if already installed)
- Skeleton implementation details
- Whether sort is client-side (preferred, no extra API calls) or server-side

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `components/ChatInterface.tsx` — contains `FoodCard` component (collapsible card with kcal, macros, nutrient detail). Reuse directly for the log list.
- `app/api/diet/route.ts` — fetches meals + foodItems for a date, auth-gated via `auth()`. Returns `meals[]` with nested `foodItems[]`. Log page can call this or a variant.
- `components/ui/` — shadcn Button, Badge, Card, Collapsible, Separator all available
- `components/BottomNav.tsx` — "Log" tab already routes to `/`

### Established Patterns
- Auth: `import { auth } from '@/app/lib/auth'` in server components / API routes
- Client components: `'use client'` directive, fetch via `fetch('/api/...')` 
- shadcn components for all UI primitives
- Prisma via `import { prisma } from '@/app/lib/prisma'`
- Mobile-first: fixed bottom nav (h-16), fixed bottom input bar, scroll area fills remaining height

### Integration Points
- `app/page.tsx` — currently renders `<ChatInterface />` for authenticated users. This will need to render the new log view instead (or ChatInterface needs to be redesigned to include the log).
- `ChatInterface.tsx` — the `handleSubmit` function triggers the meal log. After success, it should trigger a list refresh (via callback or state lift or router.refresh).
- New: `app/api/meals/[mealId]/route.ts` — DELETE handler

</code_context>

<specifics>
## Specific Ideas

- User explicitly requested sort options: Chronological, Protein, Fat, Carbs, Fiber (exact labels)
- Sort is applied to the flat list of food items (not grouped by meal)
- Delete is at meal granularity (not per food item)
- The Log tab is the "history" view — replaces the ephemeral chat stream

</specifics>
