## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → GET /api/meals/today | Unauthenticated or cross-user read attempt |
| Client → DELETE /api/meals/[mealId] | IDOR — authenticated user attempts to delete another user's meal, or orphan meal from pre-auth era |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03.2-02 | Information Disclosure | GET /api/meals/today | mitigate | auth() guard — returns 401 if no session; meals query scoped to userId in WHERE clause — user never sees another user's data |
| T-03.2-03 | Tampering / IDOR | DELETE /api/meals/[mealId] | mitigate | Check meal.userId === null \|\| meal.userId !== userId before delete; return 403 in both cases — prevents orphan meal deletion and cross-user delete |
| T-03.2-04 | Elevation of Privilege | DELETE /api/meals/[mealId] | mitigate | 401 returned if session absent — unauthenticated callers cannot reach the ownership check |
| T-03.2-05 | Tampering | FoodCard onDelete prop | accept | onDelete is a client-side React prop callback; the actual delete is gated server-side at DELETE /api/meals/[mealId] — client-side prop manipulation cannot bypass server auth |
| T-03.2-SC | Tampering | npm/pip/cargo installs | accept | No new npm packages in this plan — all imports are existing project dependencies |
</threat_model>
