### Sort Pill Row

```
[●Chronological] [Protein] [Fat] [Carbs] [Fiber]
```

- Container: `flex gap-2 overflow-x-auto scrollbar-hide px-4 py-2 sticky top-14 z-10 bg-background/95 backdrop-blur border-b`
- Each pill: `<Button>` variant
  - Active pill: `variant="default"` (filled, primary) — `bg-primary text-primary-foreground`
  - Inactive pill: `variant="outline"` — `border text-muted-foreground hover:text-foreground`
- Pill size: `size="sm"` height 32px — no stretch, inline width to label
- Pills do NOT wrap — horizontal scroll only; `white-space: nowrap` on each pill
- Sort order: Chronological (default, leftmost) | Protein | Fat | Carbs | Fiber

### FoodCard (reused from ChatInterface.tsx)

Reuse `FoodCard` component exactly as-is. Add a `mealId` prop and `onDelete` callback prop:

```
FoodCard props (extended):
  item: FoodItem         — existing
  mealId?: string        — new: used to identify which meal the trash icon deletes
  onDelete?: () => void  — new: called after successful delete API call
```

Delete control placement:
- Trash icon button sits in the card header row, between the kcal Badge and the expand chevron
- Icon: `Trash2` from lucide-react, `h-4 w-4`
- Button: `variant="ghost"` size wraps icon, min tap area `h-11 w-11` via padding
- Icon color: `text-muted-foreground hover:text-destructive` — subtle by default, danger color on hover
- Only rendered when `mealId` and `onDelete` are provided (backwards-compatible)

### Meal grouping in log view

- Sort is applied to the **flat list** of food items (cross-meal) — not grouped by meal
- When sorted by Protein/Fat/Carbs/Fiber: items are sorted descending by that nutrient value (nulls last)
- When sorted Chronological: items are ordered by `createdAt` ascending (meal creation time, then item order within meal)
- Each food item card still carries its `mealId` — the trash icon deletes the entire meal (cascade)
- No visual meal-group dividers — flat card list

## Interaction Contracts

### Sort Interaction

- Default sort on mount: Chronological
- Sort state is client-side only (no API call per sort change)
- Switching sort pills is instantaneous — no loading state
- Sort is applied to the flat food item array already in client state
- Selected pill visually updates immediately on tap

### Delete Interaction

1. User taps trash icon on a food item card
2. Optimistic: remove all food items belonging to that `mealId` from the visible list immediately
3. Fire `DELETE /api/meals/[mealId]` in background
4. Show Sonner toast: "Meal deleted" + "Undo" button, duration 5000ms
5. If Undo tapped within 5s: restore optimistic state, cancel or re-fetch (re-POST not required — a soft restore of local state is acceptable if the DELETE has not yet resolved; if DELETE resolved, a re-fetch is required)
6. If DELETE API call fails: restore optimistic state + show error toast "Couldn't delete meal. Please try again."

### Log Refresh Interaction

- After `handleSubmit` completes successfully in chat, the log list must refresh
- Mechanism: `router.refresh()` (Next.js App Router) OR a callback prop from parent that triggers re-fetch
- No full page reload — the chat input state must be preserved
- Refresh shows loading skeleton while new fetch is in-flight (optional: only show skeleton on initial load; subsequent refreshes can retain stale cards until new data arrives)

### Scroll Behaviour

- Sort pill row: sticky, does not scroll with content
- Food item cards: scrollable
- Chat messages: not shown in log view at all
- New cards appear at the top of the chronological list (most recent meal's items first when sorted Chronological — most recently added = last `createdAt`, so ascending by default puts breakfast first; use descending by `createdAt` for "most recent first" display)

Note on Chronological sort direction: show most-recently-logged meals at the top (descending by meal `createdAt`), food items within a meal in their original order. This matches the mental model of "what did I just eat".

## Accessibility Contracts

- Sort pill row: each `<Button>` has visible text label (no icon-only pills)
- Active sort pill: `aria-pressed="true"` on the active button
- Trash icon button: `aria-label="Delete meal"` — visible label absent, screen reader label required
- Skeleton cards: `aria-busy="true"` on the list container during loading
- Empty state: rendered as `<section aria-label="Empty log">` with heading level h2
- Delete toast: Sonner toast automatically uses `role="status"` — no extra aria needed
- FoodCard expand toggle: existing `aria-expanded` and `aria-label` preserved from ChatInterface.tsx
