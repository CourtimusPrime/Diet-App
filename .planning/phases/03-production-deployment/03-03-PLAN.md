<task type="checkpoint:human-verify">
  <name>Task 2: End-to-end smoke test — log via live URL, query via Claude Desktop MCP</name>
  <what-built>
    The live Railway app is running (Plan 02 complete). The local MCP server (mcp/server.ts)
    reads from the same Railway PostgreSQL database. Claude Desktop has the nutrilog MCP entry
    configured (done in Phase 2, Plan 02-02). This task confirms all three are wired together.
  </what-built>
  <how-to-verify>
    Step 1 — Log a new identifiable meal via the live URL:
    - Open your Railway app URL in a browser (from Plan 02).
    - Send: "I had oatmeal with blueberries for breakfast today"
    - Wait for food cards to appear. Note the meal was logged.

    Step 2 — Query via Claude Desktop MCP:
    - Open Claude Desktop (restart it if the MCP server is not connected — check the
      MCP indicator in the UI).
    - In a new conversation, ask:
      "Use get_meals to show me my meals from today"
    - Expected: Claude calls the nutrilog get_meals tool and returns a list including the
      oatmeal + blueberries meal you just logged via the Railway URL.

    Step 3 — Confirm MCP tool list loads:
    - In Claude Desktop, ask: "What MCP tools do you have available from nutrilog?"
    - Expected: All 9 tools listed:
      get_meals, get_daily_nutrition, get_deficiencies, get_nutrient_history,
      list_nutrients, get_food_details, set_goal, get_remaining_targets, search_foods

    If Step 2 fails (meal not returned):
    - Check that DATABASE_URL in ~/.config/Claude/claude_desktop_config.json matches the
      DATABASE_URL in your local .env (same Railway PostgreSQL instance).
    - Run locally: psql "$DATABASE_URL" -c "SELECT id FROM \"Meal\" ORDER BY created_at DESC LIMIT 1;"
      If the row appears here but not in MCP, the MCP server has a different DATABASE_URL.

    If Step 3 fails (tools not loading):
    - Restart Claude Desktop fully.
    - Check Claude Desktop logs for MCP connection errors.
  </how-to-verify>
  <resume-signal>
    Type "complete" if all three steps passed. Describe which step failed if not.
  </resume-signal>
