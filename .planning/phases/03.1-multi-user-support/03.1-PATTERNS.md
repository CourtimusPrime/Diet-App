```typescript
import NextAuth from 'next-auth'
import { PrismaAdapter } from '@auth/prisma-adapter'
import Credentials from 'next-auth/providers/credentials'
import Google from 'next-auth/providers/google'
import { prisma } from '@/app/lib/prisma'
// bcryptjs for password hashing (add to package.json)

export const { handlers, signIn, signOut, auth } = NextAuth({
  adapter: PrismaAdapter(prisma),
  session: { strategy: 'jwt' },
  providers: [
    Google({
      clientId: process.env.GOOGLE_CLIENT_ID!,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
    }),
    Credentials({
      credentials: { email: {}, password: {} },
      async authorize(credentials) {
        // validate credentials, return user or null
      },
    }),
  ],
  callbacks: {
    jwt({ token, user }) {
      if (user) token.id = user.id
      return token
    },
    session({ session, token }) {
      session.user.id = token.id as string
      return session
    },
  },
  pages: {
    signIn: '/sign-in',
  },
})
```

### `middleware.ts` — route protection (new file, no analog)

**No codebase analog.** Use NextAuth v5 middleware pattern.

**Target pattern:**
```typescript
import { auth } from '@/app/lib/auth'
import { NextResponse } from 'next/server'

export default auth((req) => {
  const isLoggedIn = !!req.auth
  const { pathname } = req.nextUrl

  // Always allow MCP and auth API routes
  if (pathname.startsWith('/api/mcp') || pathname.startsWith('/api/auth')) {
    return NextResponse.next()
  }

  // Redirect unauthenticated users to sign-in
  if (!isLoggedIn && !pathname.startsWith('/sign-in') && !pathname.startsWith('/sign-up')) {
    return NextResponse.redirect(new URL('/sign-in', req.url))
  }

  // Redirect authenticated users away from auth pages
  if (isLoggedIn && (pathname.startsWith('/sign-in') || pathname.startsWith('/sign-up'))) {
    return NextResponse.redirect(new URL('/', req.url))
  }

  return NextResponse.next()
})

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
}
```

**Critical:** `/api/mcp` MUST be exempted. MCP is called by local Claude Desktop without auth headers. `/api/chat` exemption is also listed in CONTEXT.md — confirm whether to exempt or protect based on whether MCP `log_food` tool calls it. Since `log_food` in `app/api/mcp/route.ts` calls `logMeal()` directly (not via HTTP), `/api/chat` is called only by the browser UI and SHOULD be protected.

## Critical Implementation Notes for Planner

### Package installs required before coding
```
npm install next-auth@5 @auth/prisma-adapter bcryptjs
npm install -D @types/bcryptjs
```
NextAuth v5 is `next-auth@5` (beta/stable as of 2025) — NOT `next-auth@4`. The import paths differ: `next-auth` (server) vs `next-auth/react` (client).

### Schema push strategy
`prisma db push` is used (not migrate). After schema changes:
```
npx prisma generate && npx prisma db push
```
The `userId String?` addition on Meal is safe for existing rows because it is nullable.

### Route group for auth pages
Use `app/(auth)/sign-in/page.tsx` with a route group `(auth)` so the sign-in/sign-up pages do NOT inherit `BottomNav` from the root layout. Alternative: conditionally render `BottomNav` only when session exists.

### MCP exemption is non-negotiable
`/api/mcp` must be excluded from auth middleware. The MCP server is called by Claude Desktop's local process with no auth headers. Blocking it will break the entire MCP integration.

### Prisma adapter + JWT session coexistence
Using `PrismaAdapter` with `strategy: 'jwt'` is valid. The adapter handles OAuth account linking (Account table) but session is stored client-side as JWT. The `Session` table from the standard Prisma adapter is not used with JWT strategy and does not need to be added to the schema.
