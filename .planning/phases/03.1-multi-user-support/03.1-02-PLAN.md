<objective>
Create the middleware that protects all app routes, the SessionProvider wrapper for the layout,
the sign-in and sign-up UI pages, and the user registration API endpoint.

Purpose: Without middleware, unauthenticated users reach the chat page. Without SessionProvider,
client components cannot read session state. Without the sign-in UI, users have no way to
authenticate. This plan wires the visible auth layer that users interact with.

Output:
- middleware.ts — route protection with MCP exemption (D-04, D-08, D-09 per CONTEXT.md)
- components/Providers.tsx — SessionProvider wrapper (D-12 shadcn/ui pattern)
- app/layout.tsx — updated to wrap with Providers (D-12)
- app/(auth)/sign-in/page.tsx — credentials + Google sign-in (D-01, D-03)
- app/(auth)/sign-up/page.tsx — email/password registration (D-04)
- app/api/auth/register/route.ts — registration endpoint with bcrypt (D-04, D-06)
</objective>

    - Redirect authenticated users away from /sign-in and /sign-up back to /

      matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
    }

    --- FILE: components/Providers.tsx ---
    Must be 'use client' because SessionProvider uses React context. layout.tsx is a Server
    Component and cannot directly use SessionProvider — it must delegate to this wrapper
    (PATTERNS.md layout section, RESEARCH.md Architectural Responsibility Map).

    ```typescript
    'use client'
    import { SessionProvider } from 'next-auth/react'
    export function Providers({ children }: { children: React.ReactNode }) {
      return <SessionProvider>{children}</SessionProvider>
    }
    ```

    --- FILE: app/layout.tsx ---
    Wrap the existing ThemeProvider + BottomNav structure with the Providers component.
    The existing layout imports ThemeProvider from '@/components/theme-provider' and BottomNav
    from '@/components/BottomNav'. Add import for Providers from '@/components/Providers'.

    Wrap the entire body content:
    ```jsx
    <Providers>
      <ThemeProvider ...>
        {children}
        <BottomNav />
      </ThemeProvider>
    </Providers>
    ```

    `usePathname()` inside BottomNav and return null if pathname starts with '/sign-in' or
    '/sign-up'. BottomNav is already a 'use client' component (uses usePathname), so this is safe.

    - handleGoogle: calls signIn('google', { callbackUrl: '/' })

    Link to /sign-up: "Don't have an account? Sign up"

    Use `className="flex flex-col items-center justify-center min-h-screen bg-background"` on the
    outer main element.

    --- FILE: app/(auth)/sign-up/page.tsx ---
    Must be 'use client'. Same card layout as sign-in.

    State: name, email, password, error (string | null), isPending (boolean)
    handleSubmit:
    1. POST to /api/auth/register with { name, email, password }
    2. If 201: call signIn('credentials', { email, password, callbackUrl: '/' }) to auto-sign-in
    3. If 409: set error = 'An account with this email already exists'
    4. If other error: set error = 'Registration failed. Please try again.'

    Fields: Name Input + Label (optional), Email Input + Label, Password Input + Label,
    "Create account" Button (full width, disabled while isPending), error display,
    link back to /sign-in: "Already have an account? Sign in"

    --- FILE: app/api/auth/register/route.ts ---
    Node.js API route — NO 'use client'. Uses Prisma and bcryptjs directly.
    Pattern from RESEARCH.md Pattern 5.

    POST handler:
    1. Parse { email, name, password } from request body
    2. Validate: if !email || !password return 400 with { error: 'Email and password required' }
    3. Check for existing user: prisma.user.findUnique({ where: { email } })
    4. If exists: return 409 with { error: 'Email already in use' }
    5. Hash: bcryptjs.hash(password, 12)
    6. Create: prisma.user.create({ data: { email, name: name ?? null, password: hashed } })
    7. Return 201 with { id: user.id, email: user.email }

    Use NextResponse.json() for all responses (consistent with existing fasting/route.ts pattern).
    Import prisma from '@/app/lib/prisma', bcryptjs from 'bcryptjs'.
    Do NOT import from auth.ts in this file — it would create a circular dependency risk.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated request → middleware | All inbound requests pass through edge middleware before reaching pages |
| browser → /api/auth/register | Untrusted email + password from registration form |
| /api/mcp | No auth — called by local Claude Desktop process, must remain open |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3.1-05 | Elevation of Privilege | middleware.ts route protection | mitigate | All routes blocked unless authenticated; explicit allowlist for /api/mcp and /api/auth |
| T-3.1-06 | Spoofing | /api/auth/register duplicate email | mitigate | findUnique check + 409 response prevents account takeover via registration |
| T-3.1-07 | Tampering | OAuth CSRF | accept | NextAuth handles state parameter + PKCE automatically (RESEARCH.md dont-hand-roll) |
| T-3.1-08 | Information Disclosure | Sign-in error messages | accept | "Invalid email or password" (not "email not found") prevents user enumeration |
| T-3.1-09 | Denial of Service | /api/auth/register open endpoint | accept | Rate limiting out of scope Phase 3.1 per CONTEXT.md deferred items; personal app with low abuse surface |
| T-3.1-SC | Tampering | npm/shadcn installs | mitigate | Only installs are shadcn input/label (already in project ecosystem) — low risk; slopcheck not required for UI primitives from same shadcn source |
</threat_model>
