       ```
       model User {
         id            String    @id @default(cuid())
         name          String?
         email         String    @unique
         emailVerified DateTime?
         image         String?
         password      String?
         createdAt     DateTime  @default(now())
         updatedAt     DateTime  @updatedAt
         accounts      Account[]
         meals         Meal[]
       }
       ```
       Note: `password String?` is null for OAuth-only users; only set for credentials users.

       Account model (for OAuth provider linking — PrismaAdapter writes here on first OAuth sign-in):
       ```
       model Account {
         id                String  @id @default(cuid())
         userId            String
         type              String
         provider          String
         providerAccountId String
         refresh_token     String? @db.Text
         access_token      String? @db.Text
         expires_at        Int?
         token_type        String?
         scope             String?
         id_token          String? @db.Text
         session_state     String?
         user              User    @relation(fields: [userId], references: [id], onDelete: Cascade)

       }
       ```

    --- FILE: app/lib/auth.ts ---
    Full Node.js config. Imports PrismaAdapter, bcryptjs, and the existing prisma singleton from
    '@/app/lib/prisma'. NEVER create a second PrismaClient here — reuse the singleton (RESEARCH.md
    Pitfall 5).

    Spread authConfig from './auth.config' then override providers with the full Credentials
    authorize implementation:

    Credentials authorize logic:
    - If credentials.email or credentials.password are empty/missing, return null
    - Call prisma.user.findUnique({ where: { email: credentials.email as string } })
    - If no user found, or user.password is null (OAuth-only user), return null
    - Call bcryptjs.compare(credentials.password as string, user.password)
    - If valid, return { id: user.id, email: user.email, name: user.name ?? null }
    - Otherwise return null

    JWT callbacks:
    - jwt({ token, user }): if user?.id exists, set token.id = user.id; return token
    - session({ session, token }): if token.id exists, set session.user.id = token.id as string; return session

    Session strategy: 'jwt'
    Adapter: PrismaAdapter(prisma)

    Export: export const { handlers, signIn, signOut, auth } = NextAuth({ ...authConfig, ... })

          id: string
        } & DefaultSession['user']

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/auth/[...nextauth] | Untrusted credentials and OAuth callbacks enter here |
| NextAuth authorize → Prisma | Password comparison runs server-side only, never exposed to client |
| AUTH_SECRET | Signs JWT tokens — must be set as Railway secret, never committed to git |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3.1-01 | Spoofing | Credentials authorize in auth.ts | mitigate | bcryptjs.compare with cost factor 12; constant-time comparison prevents timing attacks |
| T-3.1-02 | Tampering | JWT token signing | mitigate | AUTH_SECRET (min 32 chars) required; NextAuth signs all JWTs with HS256 |
| T-3.1-03 | Tampering | prisma/schema.prisma userId nullable | accept | Existing meals without userId remain accessible; new meals receive userId from session — intentional per D-11 |
| T-3.1-04 | Information Disclosure | User.password field in DB | mitigate | password stored as bcrypt hash only; never returned in auth() session object; NextAuth callbacks return only id/email/name |
| T-3.1-SC | Tampering | npm install next-auth@beta bcryptjs | mitigate | Package legitimacy audit in RESEARCH.md confirms all packages Approved; bcryptjs SUS flag is documented false positive |
</threat_model>
