# Phase 3.1: Multi-User Support — Context

## Objective

Add authentication (email/password + Google OAuth) to NutriLog so multiple users can each have their own meal log. Includes a landing page, auth screens, session management, and data isolation per user.

## Codebase State Going In

- **Stack**: Next.js 14 App Router, Prisma 7, Railway PostgreSQL, shadcn/ui, next-themes, bun
- **No auth**: Zero auth packages installed, all routes unauthenticated
- **DB**: Meal and FoodItem tables have no userId foreign key — data is shared/global currently
- **Routes**: `/` → ChatInterface; `/diet`, `/fasting` exist as additional pages
- **Deployed at**: `https://diet-app-production-1d69.up.railway.app`
- **Prisma schema**: Uses `db push` (not migrations)

## Phase 3.1 Success Criteria

1. Unauthenticated users see a sign-in screen instead of the chat interface
2. Email/password registration and sign-in works
3. Google OAuth sign-in works (new or returning user)
4. Signed-in users see their own meals only (filtered by userId)
5. Sign-out clears session and redirects to sign-in
6. Railway env vars `NEXTAUTH_SECRET`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` documented in `.env.example`

## Scope Fences

- **IN**: Auth flows (email/password + Google), session management, route protection, User model in DB, Meal.userId FK, landing/sign-in page, sign-out
- **OUT**: Email verification, password reset, user profile page, admin panel, rate limiting by user
- **OUT**: MCP auth — MCP server runs locally, no auth needed on `/api/mcp`

## Key Constraints

- NextAuth v5 requires `NEXTAUTH_SECRET` (32+ char random string) in env
- Google OAuth requires: Google Cloud Console project, OAuth consent screen, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`
- NextAuth v5 callback URL: `NEXTAUTH_URL` required in production (`https://diet-app-production-1d69.up.railway.app`)
- Prisma adapter for NextAuth v5: `@auth/prisma-adapter` package
- `userId` on Meal is nullable (existing meals have no owner) — chat API must set userId from session on new meals
- Middleware must exempt `/api/mcp` and `/api/chat` (MCP server calls these) or handle auth gracefully
